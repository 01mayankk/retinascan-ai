PIPELINE TRANSPARENCY
Dataset & Training Methodology

        
      

      

        This summary reflects the checked-in preprocessing scripts, training notebooks, and inference code. It distinguishes implemented steps from experiments whose dataset lineage is not established in the repository.
      


      

        

          
Labeling and class balance

          
    
            
  • Labels: classify_images.py reads train.csv, matches id_code to a PNG in raw_images, and copies it into the directory named by diagnosis (0–4).
    • 
            
  • Class names: 0 No DR, 1 Mild DR, 2 Moderate DR, 3 Severe DR, and 4 Proliferative DR.
    • 
            
  • Balancing: balance_dataset.py targets 300 files per class. It randomly samples down larger classes; smaller classes keep their originals and are filled using horizontal flips, rotations up to 20°, and brightness/contrast jitter of 0.2.
    • 
            
  • Limitations: Original per-class counts are unavailable because the dataset is not included. Random sampling has no fixed seed, the active notebook training setup does not use class weights, and the balancing script does not clear an existing output folder before copying.
    • 
          

        


        

          
Split and dataset provenance

          
    
            
  • Scripted split: split_dataset.py shuffles each numeric class independently and copies 70% to train, 15% to validation, and the remainder to test.
    • 
            
  • Illustrative counts: If all five classes contain exactly 300 files, this split yields 210 / 45 / 45 per class (1,050 / 225 / 225 total).
    • 
            
  • Leakage risk: Balancing/augmentation runs before splitting, and the split is by file rather than source-image group. Related augmented copies could therefore cross splits; no group-level leakage prevention is implemented.
    • 
            
  • Unverified link: Training notebooks load enhanced_train, enhanced_val, and enhanced_test. The repository does not establish that these are produced from the script-generated train, val, and test folders.
    • 
          

        


        

          
Training and safeguards

          
    
            
  • EfficientNet-B2: Notebook 05 uses pretrained default weights, fine-tunes the final two feature blocks, and adds dropout (0.4). The active setup uses cross-entropy, AdamW, ReduceLROnPlateau, a 100-epoch maximum, and early stopping after 15 epochs without validation-loss improvement.
    • 
            
  • DenseNet121: Notebook 07 trains in three phases: classifier only, then Transition3 and DenseBlock4, then the full network. The deployed inference config loads the phase-2 checkpoint. The final notebook phase adds label smoothing and weight decay, but that phase-3 checkpoint is not the one loaded by the app.
    • 
            
  • Augmentation: Training notebooks apply random image transforms to training batches. Validation and test transforms resize and normalize without those random augmentations.
    • 
          

        


        

          
Inference and explainability

          
    
            
  • Live input transform: Convert to RGB, resize to 300 × 300, convert to tensor, and apply ImageNet mean/std normalization. The inference code does not apply CLAHE, cropping, or sharpening.
    • 
            
  • Ensemble: Softmax probabilities are combined with DenseNet121 weight 0.6 and EfficientNet-B2 weight 0.4.
    • 
            
  • Grad-CAM: The heatmap uses the final DenseNet121 feature layer. Highlighted regions are model attribution, not confirmed lesions.
    • 
            
  • Image-quality experiments: Notebook 04 explores LAB CLAHE and conditional sharpening, but no checked-in call connects that experiment to the training data path or live inference.
    • 
          

        

      


      

        Evaluation context
        
Stored notebook outputs report 68.89% EfficientNet-B2 test accuracy with TTA, 68.00% DenseNet121 test accuracy, and 70.22% ensemble test accuracy on the notebooks’ enhanced_test path. These are historical notebook outputs, not independently reproduced or a guarantee of current clinical performance. The source does not establish the training-data lineage for the deployed checkpoints.
